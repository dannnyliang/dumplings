# 不建立信用卡結帳日與帳單期別模型

account-based-ledger 改版把「共同卡」定義為一種付款方式：消費計入當月費用，現金要到帳單扣款日才離開共同帳戶。這帶出一個建模選擇：要不要讓系統知道這張卡的結帳日與帳單週期，自動判斷每筆消費落在哪一期帳單？

決定：**不建模。共同卡未出帳 ＝ 累計共同卡消費 − 累計帳單扣款，帳單扣款由使用者輸入實際金額。**

理由：3/20 刷的卡可能落在 4 月或 5 月帳單，取決於結帳日。要正確建模需要三組規則——結帳日、帳單週期、消費跨期歸屬——複雜度不符兩人專案的收益。改用「使用者輸入實際帳單金額」後，即使某期的歸屬猜錯，差額會自然留在未出帳，於後續扣款收斂，不需要任何期別規則。

## Consequences

- **帳單日前後數天的「未出帳」數字會偏離真實卡片餘額**——已刷未入帳單的消費和已入帳單未扣款的消費混在同一個數字裡。這是本決定的已知代價，長期收斂。
- 帳單金額與 app 累計未出帳不符時顯示差額提示（`CashMovementFormModal`）。在「共同卡只用於共同開銷」的前提下，對不上即代表有漏記——這是整個設計唯一的自動偵錯機制，其可靠性取決於使用習慣（design.md R3）。
- 帳單扣款是**人工維護的狀態**：連續數月忘記輸入會讓「可動用」嚴重低估（design.md R1，最高風險）。緩解手段（帳單日提醒）尚未實作。
- 未出帳可以暫時為負（扣款金額大於累計消費），UI 以 `+` 顯示、下期收斂，不做額外約束。
